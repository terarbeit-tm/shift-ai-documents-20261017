UI / UX

User Interface / User Experience基本

意味

UIは「画面の見た目と、操作する部品」（ボタン・文字・色など）。UXは「使ったときの体験全体」（迷わず目的を達成できたか）です。UIは、UXをよくするための手段です。

使いどころ

ページを直すときは、「見た目をよくしたい」ではなく「利用者が迷わず目的を達成できるようにしたい」から考えます。

表示見本

UI（部品の見た目）

ボタン入力欄

UX（体験の流れ）

  1. 選ぶ
  2. 確認する
  3. 完了

迷わず最後まで進めれば、よいUX

Codexへの指示例

指示例
利用者が迷わず目的を達成できるように、このページのUI（見た目・操作）を改善してください。
文章・リンク・機能は変えないでください。

モーダル

Modal部品

意味

画面の上に重ねて表示する小さな画面（ポップアップ）です。開いている間は、後ろのページを操作できません。

使いどころ

長い文章（プロンプトなど）を、必要なときだけ見せたいとき。確認や入力など、いま集中してほしい操作に使います。常に読ませたい手順は、入れません。

表示見本

モーダルの見本

開いている間、後ろのページは操作できません。

この見本は枠の中で動きます。背景の暗い部分か「閉じる」で閉じられます。

Codexへの指示例

指示例
長いプロンプトを、ボタンで開くモーダル（ポップアップ）にしてください。
開く・閉じる・全文コピーができ、Escキーでも閉じられるようにしてください。

タブ

Tabs部品

意味

同じ場所で、表示する内容を切り替える見出しの並びです。

使いどころ

工程や種類ごとに情報を分けて、いま必要な分だけ見せたいとき。

表示見本

手順：やることを順に書きます。
理由：なぜ必要かを書きます。
確認：できたかどうかを確かめます。

Codexへの指示例

指示例
工程ごとにタブで切り替えられるようにしてください。
現在選択中のタブが分かる見た目にし、キーボードでも操作できるようにしてください。

アコーディオン

Accordion部品

意味

見出しを押すと、中身が開いたり閉じたりする表示です。

使いどころ

補足や見本など、必要な人だけ読めばよい情報。必須の手順は閉じません。

表示見本

よくある質問（押すと開きます）

ここに答えが入ります。

もうひとつの質問

必要な人だけが開いて読みます。

Codexへの指示例

指示例
よくある質問を、見出しを押すと開くアコーディオンにしてください。
最初は閉じておき、必須の手順は折りたたまないでください。

1カラム／2カラム

Columnsレイアウト

意味

画面を縦の列で区切った構成です。1カラムは本文が縦一列、2カラムは本文の横に目次などを置く構成です。

使いどころ

読み物は1カラム。目次や関連リンクを常に見せたいなら2カラム。スマホでは1カラムに戻すのが基本です。

表示見本

1カラム

2カラム

Codexへの指示例

指示例
本文を2カラム（本文と、右側の目次）にしてください。
スマホでは1カラムに戻してください。

レスポンシブ

Responsive designレイアウト

意味

画面の幅（PC・スマホ）に合わせて、レイアウトが自動で変わる作りです。

使いどころ

PCでもスマホでも見られるページ。横スクロールが出ないこと、文字や押す部分が小さくなりすぎないことが目安です。

表示見本

PCの幅（3列）

スマホの幅（1列）

Codexへの指示例

指示例
スマホ（画面幅360〜390px）でも見やすいレスポンシブ表示にしてください。
横スクロールが出ないようにし、ボタンは押しやすい大きさにしてください。

モックアップ

Mockupレイアウト

意味

完成後の画面イメージを見せる、見本の画面枠（PCやスマホの画面）です。

使いどころ

操作画面や完成イメージを、文章より早く伝えたいとき。

表示見本

Codexへの指示例

指示例
説明の近くに、PC画面とスマホ画面のモックアップを入れてください。
画像は後から差し替えられる枠にし、代替テキスト（alt）を付けてください。

カードUI

Card UI部品

意味

関連する情報を、枠で囲んだ小さな面にまとめる見せ方です。

使いどころ

種類の違う情報を並べて、役割を見分けやすくしたいとき（手順・補足・配布ファイルなど）。

表示見本

手順やること
補足知っておくこと
配布ダウンロード

Codexへの指示例

指示例
手順・補足・配布ファイルを、役割が分かるカードUIに分けてください。
カードごとに見出しと余白をそろえてください。

ヘッダー

Headerレイアウト

意味

ページの一番上にある、タイトルやロゴ、メニューを置く帯です。

使いどころ

いま見ているサイトが何か、どこへ移動できるかを、最初に伝えたいとき。

表示見本

サイト名メニュー

Codexへの指示例

指示例
ページの上部に、サイト名と主要メニューを置いたヘッダーを作ってください。
スマホでも1行に収まるようにしてください。

ナビゲーション

Navigation部品

意味

ページ間・ページ内を移動するためのメニューです。

使いどころ

どこにいるか（現在地）と、次にどこへ行けるかを示したいとき。現在地は、色だけでなく下線などでも示します。

表示見本

午前午後応用編用語集

現在地は、色・太さ・下線で示しています。

Codexへの指示例

指示例
午前・午後・応用編・用語集へ移動できるナビゲーションを、全ページの上部に置いてください。
現在のページが分かる表示にしてください。

CTA

Call To Action部品

意味

「ダウンロードする」「申し込む」のように、次の行動をうながすボタンやリンクです。

使いどころ

読んだ人にしてほしい行動が1つあるとき。目立たせるのは、1ページに1〜2個までにします。

表示見本

資料をダウンロードあとで読む

主なボタンだけを目立たせています。

Codexへの指示例

指示例
ページの最後に、「資料をダウンロード」のCTAボタンを置いてください。
主なボタンは1つだけ目立たせ、他は控えめにしてください。

ヒーローセクション

Hero sectionレイアウト

意味

ページを開いて最初に見える、大きな見出しと一言説明の領域です。

使いどころ

ページの目的を、最初の数秒で伝えたいとき。

表示見本

ひと目で分かる題名1行の説明はじめる

Codexへの指示例

指示例
ページの最初に、題名と1行の説明、主なボタンを置いたヒーローセクションを作ってください。
文章量は少なくしてください。

ホバー

Hover見た目・操作

意味

マウスを重ねたときに、見た目が変わることです。「押せる場所」を伝える合図になります。

使いどころ

ボタン・リンク・カードなど、押せる場所を示したいとき。スマホにはホバーがないので、ホバーだけに頼りません。

表示見本

マウスを重ねてみてください

キーボードでフォーカスしても、同じ見た目になります。

Codexへの指示例

指示例
ボタンとカードに、マウスを重ねたときの見た目の変化（ホバー）を付けてください。
スマホでも使えるように、ホバーだけに頼らない作りにしてください。

アクセントカラー

Accent color見た目・操作

意味

基本の色に加えて、強調したい所だけに使う色です。

使いどころ

ボタンやリンクなど、目を向けてほしい所だけに使います。使いすぎると、どこが大事か分からなくなります。

表示見本

基本背景強調
強調の色はここだけ

Codexへの指示例

指示例
アクセントカラーを1色に決めて、ボタン・リンク・見出しの印だけに使ってください。
文字と背景の明暗差は確保してください。

余白

Whitespace見た目・操作

意味

文字や部品のまわりの、何も置かない空きです。

使いどころ

情報のまとまりを見分けやすくしたいとき。詰め込むほど、読みにくくなります。

表示見本

余白が少ない

見出し

本文が続きます。まとまりが分かりにくい。

見出し

次の本文です。

余白がある

見出し

本文が続きます。まとまりが見分けやすい。

見出し

次の本文です。

Codexへの指示例

指示例
見出しと本文、カードとカードの間の余白を広げて、まとまりが見分けやすいようにしてください。
文章は変えないでください。

ステップ表示・チェックリスト

Steps / Checklist部品

意味

手順に番号を付けて順番を示す表示と、できたかどうかを確かめる確認欄です。

使いどころ

操作手順など、順番どおりに進めてほしい情報。「できたら確認」を付けると、次へ進んでよいか迷いません。

表示見本

  1. ファイルを開く
  2. プロンプトをコピーする
  3. 貼り付けて実行する

Codexへの指示例

指示例
手順に番号を付けたステップ表示にし、各ステップの終わりに「できたら確認」のチェック欄を付けてください。
手順の文章は変えないでください。
